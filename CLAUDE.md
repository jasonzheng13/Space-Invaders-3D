# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A 3D Space Invaders clone in Unity **6000.6.0f1** using the Universal Render Pipeline (started from the URP Empty Template) and the new **Input System** package. All gameplay code lives flat in `Assets/` (six MonoBehaviours, no assembly definitions, no tests). The single scene is `Assets/Scenes/SampleScene.unity`.

## Commands

The `unity` CLI is installed (`~/.unity/bin/unity`) and the matching editor is at `/Applications/Unity/Hub/Editor/6000.6.0f1`. Run from the repo root.

```bash
unity open                                   # open the project in the correct editor
unity build --profile "Web - Desktop - Development" -o Builds/web   # the only build profile (Assets/Settings/Build Profiles)
unity build --target StandaloneOSX -o Builds/mac
unity test --mode PlayMode                   # or --mode EditMode; writes test-results.xml
unity test --mode PlayMode --filter "SomeTestName"   # single test
unity status                                 # see connected editor instances
```

There are no tests yet; `com.unity.test-framework` is in the manifest, so adding `Assets/Tests/` with an asmdef is all that is needed. `Library/`, `Temp/`, `Logs/`, `UserSettings/` are gitignored and regenerated by the editor.

## Architecture

**Scene wiring.** `SampleScene` contains two prefab instances, `Spaceship` and `AlienFleet`, plus a uGUI `Canvas` whose `AlienCounter` (TextMeshProUGUI) is referenced by the fleet. `AlienFleet.Start()` spawns a 10x3 grid of `Alien` prefabs, keeps them in its public `aliens` list, and sets each `Alien.fleet` back-reference. Nothing else creates or tracks aliens, so:

- The `aliens` list is the single source of truth. `AlienFleet.Update()` copies `aliens.Count` into `AlienCounter.score` every frame; `Alien.OnCollisionEnter` removes itself from the list before destroying itself.
- An `Alien` dropped into the scene by hand has a null `fleet` and will throw on collision.

**Movement is manual, not physics-driven.** Every moving object (`AlienFleet`, `Dart`, `AlienBullet`) sets `transform.position` directly in `FixedUpdate` with a per-tick step, so speeds are in units per physics tick, not per second. `Spaceship` is the exception: it moves in `Update` scaled by `Time.deltaTime`. Rigidbodies exist only so `OnCollisionEnter` fires; gravity is off on all of them and the spaceship's is kinematic.

**Collisions are routed by physics layers**, not tags (the tag list is empty). Layers 6-9 are `Spaceship`, `Alien`, `Bullet`, `Alien_Bullet`, and the collision matrix in `ProjectSettings/DynamicsManager.asset` disables `Bullet`<->`Spaceship` and `Alien_Bullet`<->`Alien`. So darts only hit aliens and alien bullets; alien bullets only hit the spaceship and darts. `Dart` has no collision handler: the thing it hits (`Alien` or `AlienBullet`) destroys both parties. Keep that in mind when adding a new collidable: assign a layer and update the matrix rather than filtering in code.

**Fleet motion.** `AlienFleet.speed` encodes direction by sign. When the fleet's outermost alien crosses `leftBound`/`rightBound`, the sign flips and `movingDown` is set; an `Invoke("startSidewaysMotion", downTime)` clears it. The `lowerBound` check is currently commented out, so the fleet never stops descending.

**Projectile lifetime** is bounds-based: `Dart` destroys itself above y=10, `AlienBullet` below y=-10. Alien firing is a per-tick random roll (`bulletSpawnRate`) gated by `shotCooldown`.

**Input.** `Spaceship` polls `Keyboard.current` (arrow keys, space) directly. `Assets/InputSystem_Actions.inputactions` is the template's default action map and is not used by gameplay code.

## Conventions

- Inspector fields use `[Header("Inscribed")]` for values set in the Inspector/prefab and `[Header("Dynamic")]` for runtime state (the Gibson *Introduction to Game Design, Prototyping, and Development* convention). Follow it when adding public fields.
- Tunables are often `static` floats (`Dart.speed`, `Alien.shotCooldown`), so they are not editable in the Inspector; make a field non-static if it needs per-prefab tuning.
- Prefab references (`bulletPrefab`, `dartPrefab`, `alienPrefab`, `alienCounter`) are assigned in the `.prefab`/scene YAML, so renaming or moving a script changes nothing, but deleting a `.meta` file breaks those links.
